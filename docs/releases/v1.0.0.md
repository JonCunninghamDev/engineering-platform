# Engineering Platform v1.0.0

## Release intent

`v1.0.0` is the first stable, consumer-ready Engineering Platform contract. It establishes the platform surfaces required to validate adoption from an external repository while keeping product-specific architecture and policy in the consuming repository.

## Included platform capabilities

- governed Context, Orchestrator, Builder, and Verifier agent pipeline;
- deterministic, inspectable handoff artifacts and evidence;
- tier-aware execution and explicit locked-capability reporting;
- machine-readable capability and engineering-policy contracts;
- reusable consumer CI composition through generic capability/profile inputs;
- compatibility, upgrade, release-verification, failure-isolation, and rollback contracts;
- protected-path and pull-request policy validation that fails closed;
- `main`/`develop` delivery governance with temporary work branches;
- explicit metadata-only `release/X.Y.Z -> develop` preparation route;
- separate human-approved `develop -> main` production promotion route.

## Consumer contract

Consumers should pin both the immutable `v1.0.0` tag and its resolved release commit. Local synchronized steering and policy remain checked into the consumer so normal operation, testing, and rollback do not depend on runtime access to this repository.

Consumer-specific prerequisites, branch rules, visual gates, exceptions, and migration work remain owned by the consumer repository. The Engineering Platform must not depend on consumer identity or product architecture.

## Validation

Before publication, the release preparation must pass the complete Platform CI required for the governed release-preparation route. Production publication occurs only after explicit human approval of the subsequent `develop -> main` release promotion and successful release CI on `main`.

## Next validation milestone

After publication, validate the external consumer adoption contract described by issue #5 using generic, consumer-agnostic fixtures and evidence. Measured multi-agent scaling remains deferred until a consumer operates successfully on the released platform and a single-agent baseline exists.
